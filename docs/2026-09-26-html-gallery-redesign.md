# 拾页 · HTML Gallery：品牌、前端与内容流程设计

日期：2026-09-26
状态：初始设计记录。现已采用 A 方案实施纯静态版；按后续要求移除添加/管理入口，使用 content/ 分类目录、catalog.json 和一键发布脚本，加入明暗主题。下文的本地工作台为历史提案，不属于当前产品。

## 1. 产品定位与现状

从 HTML 演示文稿目录升级为个人 HTML 作品展示站，服务两类任务：访客快速找到并打开作品，维护者快速收录并发布作品。

已检查 build.js、templates/index.html、scripts/screenshots.js、scripts/deploy.sh、routes.json、vercel.json、现有测试与作品元信息。当前有 13 个 HTML 文件，涵盖演示文稿、游戏、个人网站和交互实验。

当前首页使用黑底、蓝色强调、发光标记、WebGL 背景和统一卡片网格；缺少搜索、分类、标签及内容管理。构建只扫描 slides/ 顶层 HTML，标题与摘要由 HTML 提取；本地生成缩略图，部署环境复制预置图片。发布脚本执行构建、暂存所有变更、提交、推送。

## 2. 改版边界

- 模式：Redesign · Overhaul，重做展示站身份与信息组织。
- 保留：13 个作品原文、现有访问地址与 routes.json 映射、静态站点产物、真实缩略图、键盘可访问性、图片尺寸声明和按需加载。
- 改善：品牌辨识、首屏作品密度、内容查找、元信息录入、缩略图反馈、发布前检查。
- 移除：首页装饰性 WebGL 背景、仅适用于 PPT 的措辞、访客无须知道的构建工具宣传。作品内部视觉和脚本不属于首页重做范围。
- 最高风险：路由迁移、相对资源路径、管理入口误暴露；采用兼容既有路由、本地管理服务与发布产物隔离处理。
- 回退：改动分模块组织，内容源文件不迁移；新元数据缺失时仍能从 HTML 提取信息并展示。

## 4. 品牌与设计系统

拟用品牌：**拾页 / HTML GALLERY**。
主张：**把灵感，打开成一页。**
解释文案：收集演示、游戏、网站与交互实验，每一页都可以直接体验。

四个定位判断：

1. 叙事角色：这是进入作品的目录首页，标题负责识别，预览负责吸引，筛选负责效率。
2. 观看距离：笔记本与手机日常浏览，正文 16px，标题流式 40–72px，触控目标至少 44px。
3. 视觉温度：安静、有创造力、轻编辑感；强调内容本身。
4. 容量：13 件作品适合单页即时筛选，不增加分页和额外落地页；长标题允许换行。

设计 tokens：

- 页面：纸白 #F6F5F0；表面 #FFFFFF；主文字 #20251F。
- 次文字 #636B60；边框 #DDDFD5；品牌墨绿 #52634A；强调嫩绿 #D8EF7D（配深色文字）。
- 展示字体：Georgia / Songti SC / STSong 衬线栈，用于品牌与主标题；正文 PingFang SC / Microsoft YaHei / sans-serif。采用本地字体回退，无外部字体请求。
- 间距：4px 基准，8/12/16/24/32/48/64/96px；内容宽度上限 1360px。
- 圆角：预览 12px、控件 8px、标签胶囊；不将所有信息包成多层卡片。
- 阴影：默认平面与细边框，仅浮层和悬停提供轻阴影。
- 动效：140–220ms，cubic-bezier(.2,.8,.2,1)；减少动态效果偏好下关闭非必要运动。
- 品牌资产：确认命名后制作原创“页签/翻页”矢量标记与 favicon，记录在 brand-spec.md；不引入外部品牌标志。

## 5. 首页结构与浏览体验

```text
拾页 / HTML GALLERY                           全部作品 · 收录指南
──────────────────────────────────────────────────────────────
把灵感，打开成一页。                      实际作品数 / 类型索引
演示、游戏、网站与交互实验。

[ 搜索作品名称、描述或标签…                              / ]
[全部] [演示文稿] [网站] [交互实验] [游戏]
标签  [AI] [网络协议] [3D] [创意编程] …            清除筛选
──────────────────────────────────────────────────────────────
显示 n / 13 件作品                    排序：收录时间 / 名称

[真实预览图]         [真实预览图]         [真实预览图]
编号 / 类型         编号 / 类型         编号 / 类型
作品标题            作品标题            作品标题
简短描述            简短描述            简短描述
主题标签 / 打开      主题标签 / 打开      主题标签 / 打开
```

- 分类是作品形式，单选；标签是主题，多选，多个标签采用“同时匹配”，界面明确说明。搜索、分类和标签共同生效。
- 计数来自实际内容；没有匹配结果时显示当前条件和“清除筛选”，不出现空白页。
- 筛选同步 URL 查询参数；复制地址可分享同一结果，浏览器后退恢复条件。
- 搜索快捷键 / 在非输入区域生效；所有控件具有可见焦点，筛选结果数量以适当的 live region 通知。
- 缩略图链接直接打开独立作品；标签按钮不嵌套在整卡链接内，避免点击冲突。
- 手机端搜索和分类便于触达，标签可换行；不依赖悬停发现主要操作。
- 公共首页默认只显示浏览功能与收录说明；本地工作台才显示“添加作品”和编辑操作。
- 无 JavaScript 时仍可浏览完整作品列表；筛选是渐进增强。

## 6. 内容模型与兼容

保留 slides/ 与 routes.json，增加 content.json 保存可编辑元数据。路径与展示信息职责清晰，不建立两个互相冲突的路由来源。

元数据以源文件相对路径作为键，字段包括：title、description、category、tags、addedAt、featured（可选）、thumbnail（可选自定义封面）。

- 显示标题/摘要优先使用元数据，缺失时解析 HTML，最后用文件名兜底。
- category 采用固定、可配置的形式分类；tags 去首尾空格、去重，保留中文。
- 新导入内容记录实际收录时间；历史内容优先读取可验证的 Git 记录，没有依据则不展示日期，不能每次构建伪造“刚更新”。
- 老文件及老路由原样兼容。新增资源文件夹采用 slides/<slug>/index.html + 相对资源，构建复制相应目录并维护访问路径。
- 嵌套 HTML 作为主入口还是资源必须明确指定，不能把每个辅助 HTML 自动当成新作品。
- 预览沿用已有截图缓存；自定义封面可覆盖，失败显示明确占位，保留重试操作。

## 7. 添加与发布：完整路径

### 主路径：本地可视化收录

拟新增命令 npm run studio，启动仅监听 127.0.0.1 的本地工作台。

1. 拖入 HTML 文件或选择一个包含 HTML 入口与资源的目录。
2. 自动识别标题、描述，预填文件名与访问地址。
3. 用户确认分类、标签和可选描述；路径重复时说明冲突，不静默覆盖。
4. 保存源文件与 content.json；生成封面并反馈处理中、成功或失败状态。
5. 打开本地预览，检查作品及卡片；需要时修改元数据或更换封面。
6. 执行发布前检查，展示即将发布的内容变更，再由维护者发起既有 Git 发布。

本地工作台应具有真实的落盘能力，不将文件只放进浏览器内存或 localStorage。公开静态网站不提供能写仓库的匿名接口。本地写入接口校验请求来源、会话凭据、路径及文件大小；预览导入 HTML 与管理页面隔离，防止作品脚本获得管理权限。

### 快捷路径：命令导入

拟新增 npm run add -- <文件或目录>，支持标题、分类、标签、路由等参数；核心导入逻辑与工作台共用。直接将 HTML 放进 slides/ 的旧路径仍可使用，缺失分类显示“未分类”。

### 构建与发布职责

- 开发预览：快速重建索引，优先复用封面，不因未变化的作品重复启动截图。
- 内容检查：JSON 结构、源文件存在性、路由唯一性、保留路径冲突、相对资源和封面状态。
- 正式构建：校验通过后生成静态首页、作品文件与本地前端资源；保持既有部署平台配置可用。
- 截图：可独立触发或在导入后执行；失败不阻塞查看作品，提示重试。
- 发布：改进脚本的变更摘要及暂存范围，避免当前 git add -A 意外带入无关文件；此轮开发本身不自动提交或推送。

## 9. 验证标准

- 13 个旧作品均可打开，既有路由保持不变，作品 HTML 内容不被改写。
- 搜索/分类/多标签组合、无结果、重置和 URL 恢复具有可验证行为。
- 添加单文件与带资源目录都能完成落盘、生成首页条目、预览和再次编辑。
- 拒绝路径越界、路由冲突、非法元数据；导入失败不能留下看似成功的条目。
- 无管理服务时公开站点仍完整可用；发布产物不包含本地写入端点。
- 更新现有绑定旧动画细节的测试，保留图片尺寸、加载优先级、可访问性和兼容行为检查。
- 执行内容校验、自动化逻辑测试与正式构建；响应式和减少动态效果规则进行代码自检。
- 只有另行要求浏览器验收时，再运行跨视口浏览器验收流程。

# 索引页响应式布局优化设计

## 背景与目标

当前 `templates/index.html` 生成的首页索引存在以下问题：

1. **卡片过宽**：索引页采用单列 flex 布局，卡片占满 `max-width: 860px` 的容器，在大屏下显得过于修长。
2. **图片展示不完整**：缩略图使用固定高度 `140px` + `object-fit: cover; object-position: top`，导致截图上下被裁剪，无法完整呈现幻灯片封面内容。
3. **缺乏响应式**：仅有针对 `max-width: 640px` 的简单微调，未充分利用大屏空间。

本次优化的目标：将索引页改为响应式多列网格，统一缩略图比例，使页面在桌面、平板、手机上均有良好的展示效果。

## 设计决策

经过方案对比（详见 visual companion 会话），用户最终选择 **方案 C：统一比例 + cover + 悬停提示**。

选择理由：
- 多列网格能充分利用桌面端宽度，避免卡片过宽。
- 统一缩略图比例使网格整齐对齐，视觉节奏更稳定。
- `object-fit: cover` 保证缩略图区域无留白、充满容器。
- 悬停时显示完整缩略图提示，兼顾封面的视觉冲击力与查看完整截图的需求。

## 详细设计

### 布局结构

- 外层 `.page` 保持居中，适当放宽最大宽度，为网格留出空间。
- `.deck-list` 改为 CSS Grid：
  - `>= 1024px`：3 列
  - `>= 640px 且 < 1024px`：2 列
  - `< 640px`：1 列
- 网格间距（gap）保持 `16px` 或 `20px`，与现有设计一致。

### 卡片样式

- 卡片保持现有深色主题、圆角、边框与 hover 动效。
- 卡片内部结构不变：缩略图 + 标题/描述 + 底部元信息。
- 标题和描述文字在多列下适当缩小字号，避免卡片过高。

### 缩略图处理

- 缩略图容器统一使用 `aspect-ratio: 16 / 10`。
- `img` 使用 `width: 100%; height: 100%; object-fit: cover; object-position: top;`。
- 移除当前固定的 `140px` 高度。
- 保留无截图时的渐变占位图，占位图内部文字居中，高度由 `aspect-ratio` 撑开。

### 悬停提示（完整缩略图预览）

- 当鼠标悬停在卡片上时，缩略图从 `object-fit: cover` 切换为 `object-fit: contain`，在当前容器内完整显示原始截图。
- 默认状态下仍使用 `cover` 填充 16:10 容器，保证网格整齐。
- 在触屏设备上该提示不显示（通过 `@media (hover: hover) and (pointer: fine)` 限制）。

### 响应式细节

- 断点：
  - `1024px`：桌面 3 列
  - `640px`：平板 2 列
  - `< 640px`：手机 1 列
- 在单列模式下，缩略图高度可适当放大，保证手机端的可读性。
- 页面整体 padding 使用 `clamp()` 随视口缩放，与现有样式保持一致。

### 可访问性

- 保留 `:focus-visible` 焦点样式。
- 保留 `prefers-reduced-motion` 的动画禁用处理。
- 悬停提示使用 `aria-hidden="true"`，避免对屏幕阅读器造成干扰。

## 影响范围

- 仅修改 `templates/index.html` 中的内联样式。
- `templates/card.html` 与 `build.js` 的结构不需要改动（`{{THUMB_BLOCK}}`、`{{DESC_BLOCK}}` 等插槽保持不变）。
- 缩略图生成逻辑（`scripts/screenshots.js`）不受影响。

## 验收标准

- [ ] 桌面端（>=1024px）显示 3 列卡片，卡片宽度不再过长。
- [ ] 平板端（640px~1023px）显示 2 列卡片。
- [ ] 手机端（<640px）显示 1 列卡片。
- [ ] 所有缩略图统一 16:10 比例，区域被图片完整填充，无变形。
- [ ] 鼠标悬停时显示完整缩略图预览（桌面端）。
- [ ] 触屏设备不显示悬停预览，布局正常。
- [ ] 无缩略图的占位图高度与有图卡片一致。
- [ ] `npm run build` 成功生成 `public/index.html`。

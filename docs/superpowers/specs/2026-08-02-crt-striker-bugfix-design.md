# CRT Striker：Boss、续命进度与界面重叠修复设计

## 范围

修复 `slides/crt-striker.html` 中的三个问题：第一关 Boss 画面位置不随逻辑移动、故事模式续命后回到第一波，以及 Boss/HUD 和通关结果界面的文字重叠。保留既有菜单、设置和键位说明行为。

## 方案

采用“当前进度检查点 + 当前波重置”的局部方案：

1. Boss 更新函数继续只负责计算逻辑坐标；统一更新出口在每帧后同步 Boss 精灵及附属核心的位置。
2. 进入普通波、中 Boss、最终 Boss 时记录检查点。玩家死亡且仍有命时，清理当前场上的敌人、子弹和 Boss，保留分数、炸弹、强化、剩余命数及已完成波数，从当前检查点开头重新开始。
3. Boss 名称/血条整体下移，避开顶部 `STAGE/WAVE`；通关页按钮下移到统计信息之后；制作名单使用更紧凑的纵向间距。

## 状态与数据流

检查点只记录可重建的关卡进度，不保存敌人/子弹的瞬时状态：

- 普通波：`waveIndex`；重建该波的 spawn queue。
- 中 Boss：当前中 Boss 类型和必要的 `waveIndex`；重新生成中 Boss。
- 最终 Boss：Boss key 和必要的 `waveIndex`；重新生成完整生命值的 Boss。

死亡扣除命数后，重置玩家位置和短暂无敌时间，但不重置分数、炸弹、强化、擦弹累计、已完成波数或续关计数。

## 验证

使用 Playwright 在真实渲染页面中验证：

- 第一关 Boss 的逻辑坐标与精灵坐标持续一致，并从屏幕右侧进入目标位置。
- 在非第一波状态触发死亡后，续命的 `waveIndex` 保持不变，当前波从开头重新生成。
- Boss HUD 的文字边界与波数文字不相交。
- 通关页统计文字与按钮不相交，关键元素均在 1280×720 逻辑画布内。
- 内联脚本语法检查和 `git diff --check` 通过。

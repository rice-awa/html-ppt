# Agent Harness 科普 HTML 演示设计规格

## 1. 项目目标

基于 `reports/agent-harness-research-report.md`，创建一套面向大众与初学者的 1920×1080 HTML 幻灯片，用约 25 分钟通俗解释 AI Agent 工程中的 Harness：它是什么、为什么需要、由什么组成、如何改变 Agent 的实际能力，以及团队如何构建自己的外层 Harness。

演示应让观众最终记住一个核心判断：

> **Agent = Model + Harness，因此 Harness = Agent − Model。**

视觉参考 `slides/TCP-Presentation-v2.html`，继承其暖色纸张、网格底纹、粗黑描边、鲜明色块、大字号和场景动画，但不复制页面结构。新演示采用独立的“Agent 拆解实验室”叙事与视觉系统。

## 2. 受众、时长与内容边界

- **受众**：不了解 Agent 工程全貌的大众与初学者。
- **时长**：约 25 分钟。
- **页数**：18 页。
- **深度**：概念科普优先；工程术语只在帮助理解时出现，并随讲随解释。
- **重点案例**：
  - `Harness = Agent − Model` 的减法定义；
  - 报告引用的 Grok Code Fast 1 案例：编辑工具输出格式变化带来 SWE-bench 6.7% → 68.3%；
  - 长程 Agent 的 initializer、进度文件与 git history 实践；
  - 用户侧外层 Harness：规则、测试、静态分析和反馈回路。
- **不包含**：完整框架 API 教程、代码演示、详细框架选型矩阵、演讲者备注模式、动画速度控制面板。

## 3. Design Read

```yaml
artifact: 1920×1080 HTML 科普演示
audience: 对 Agent 工程缺少系统认识的大众与初学者
visual-language: 动态技术编辑风 × 工业拆解图 × 温暖纸张质感
mode: 参考风格再创作，不复制 TCP 的页面模板
visual-variance: 7/10
motion-intensity: 8/10（高强度集中在四个关键 3D 场景）
information-density: 5/10
asset-dependence: 2/10
brand-fidelity: 6/10
```

这些校准值对应以下实际决策：

- 稳定网格作为阅读脊柱，同时交替使用爆炸图、剖面、流程剧场、大数字冲击页和复杂度阶梯。
- 动画只承担拆解、因果、筛选和恢复；高强度空间动画只出现在四个关键叙事支点。
- 每页只承载一个需要记住的判断，技术术语作为第二层标注。
- 不依赖照片或外部插画，主要使用排版、几何模块、连线、状态和少量 Three.js 低多边形场景。
- 继承参考稿的暖纸张、描边与色块语言，重新设计主隐喻、角色配色与页面构图。

## 4. 叙事主线

主线为 **“拆解一台 Agent”**。

观众先看到两台使用同一模型、表现却截然不同的 Agent。随后演示将 Agent 机器拆开，通过 `Agent − Model` 得到 Harness，再逐个装回循环、上下文、工具、护栏、人类审批、持久化、编排和评测模块。最后用真实案例证明：模型权重不变，Harness 的接口和环境也可能释放数量级的能力差异。

叙事分为四幕和一个结尾：

1. 先把 Agent 拆开看；
2. 裸模型缺什么；
3. 逐层装回 Harness；
4. 为什么 Harness 真能改变能力；
5. 回到核心公式总结。

## 5. 18 页内容结构

### 第一幕：先把 Agent 拆开看（约 5 分钟）

#### 01 封面｜AI Agent 为什么不只是一颗模型？

- 中央为一台悬浮的 Agent 装置。
- 橙色模型核心正在运转，蓝色 Harness 模块处于爆炸拆解状态。
- 副标题说明主题：把“会说话”的模型变成“会做事”的系统。

#### 02 同一颗大脑，为什么表现差这么多？

- 左右两台 Agent 使用相同模型核心。
- 左侧反复中断、遗忘和误操作；右侧稳定完成任务。
- 只提出问题，不提前给答案。

#### 03 核心公式｜Agent = Model + Harness

- 完整 Agent 装置进入画面。
- 外围模块逐层脱离，模型核心留在中央。
- 公式完成减法：`AGENT − MODEL = HARNESS`。

#### 04 一句话定义｜不是模型的部分，就是 Harness

- 模型与外围设施明确分区。
- 解释 Harness 是 Agent 系统中除模型以外的代码、配置和执行逻辑。
- 建立“智能”和“让智能落地”之间的区别。

### 第二幕：裸模型缺什么（约 4 分钟）

#### 05 裸模型其实只会“接着说”

- 输入文本进入模型，模型输出后续 token。
- 明确它本身没有行动循环、长期记忆、工具执行和权限系统。

#### 06 让它独自去办事，会发生什么？

- 一条任务轨迹依次出现五类故障：
  1. 停在第一步；
  2. 忘记进度；
  3. 工具调用失控；
  4. 失败后无法恢复；
  5. 无法定位错误。
- 对应引出 Harness 要解决的问题。

#### 07 Harness 的全景剖面

- 中央模型核心，外围呈现七个模块：
  1. 循环控制；
  2. 上下文与记忆；
  3. 工具与 MCP；
  4. 护栏；
  5. 人类在环；
  6. 持久化与编排；
  7. 评测与可观测。
- 采用围绕模型的功能剖面，而不是普通七层表格。

### 第三幕：逐层装回去（约 9 分钟）

#### 08 循环控制｜Agent 的心跳

- 环形轨道展示 `Think → Act → Observe → Repeat`。
- 强调模型输出动作，Harness 负责执行、回填结果、判断是否继续和何时停止。

#### 09 上下文工程｜不是知道得多，而是此刻看对东西

- 大量资料经过筛选门，只有当前步骤需要的信息进入模型。
- 解释工作记忆、长期记忆、检索与压缩的角色。
- 结论：上下文越多不一定越好，动态选择更重要。

#### 10 工具与 MCP｜给大脑一双手

- 模型提出结构化动作。
- Harness 做参数校验、权限检查、真实执行，再将结果返回。
- MCP 被解释为统一插座，使文件、数据库、浏览器和服务可以标准化接入。

#### 11 护栏与人类在环｜刹车不是最后才装

- 危险动作在执行前冻结并进入审批。
- 同时标出输入、工具调用、输出和记忆四个检查点。
- 解释人可以批准、拒绝、修改或接管。

#### 12 持久化｜任务跑一半挂了，不必从头来

- 时间轴在中途断开，并从 checkpoint 接续。
- 用“轮班工程师”类比 initializer、进度文件、feature list 和 git history。
- 完成状态必须经过验证，不允许提前标记。

#### 13 编排｜一个 Agent 不够时，才分工

- 复杂度阶梯：单次调用 → Prompt Chain → Routing → Parallel Workers → Evaluator-Optimizer。
- 强调从最简单的方案开始，只有任务步骤无法预知时才使用完整 Agent。

#### 14 评测与可观测｜没有仪表盘，就是盲飞

- 展示一条可追踪的任务轨迹。
- 标出步骤、工具、耗时、成本、失败位置和最终质量。
- 强调只看最终答案不足以诊断 Agent。

### 第四幕：为什么 Harness 真能改变能力（约 5 分钟）

#### 15 冲击案例｜模型没变，6.7% → 68.3%

- 展示报告引用的 Grok Code Fast 1 数据。
- 从装置中抽出、翻转并重新插入 `EDIT TOOL FORMAT` 接口组件。
- 模型核心保持不变，指标从 6.7% 切换为 68.3%。
- 小字注明该数字为特定模型与评测案例，不表示 Harness 改动普遍都能获得相同比例提升。

#### 16 内层与外层 Harness｜厂商搭一层，团队还要再搭一层

- 内层：系统提示、工具运行时、检索与编排。
- 外层：项目规则、测试、静态分析、架构适应度约束与自验证反馈。
- 解释外层 Harness 的目标是让问题在到达人类前先被系统发现和纠正。

#### 17 从简开始｜什么时候才需要完整 Agent？

- 用升级阶梯说明：单次 LLM → Prompt Chain → Routing → Agent。
- 判断标准：只有在运行时无法预知所有步骤，且模型必须自行决定下一步时，Harness 才需要完整 Agent 能力。

### 结尾（约 2 分钟）

#### 18 总结｜模型决定它有多聪明，Harness 决定它能否把事做好

- 回到完整拆解图。
- 用六个短句总结：
  - 循环让它继续；
  - 上下文让它看对；
  - 工具让它行动；
  - 护栏让它不越界；
  - 持久化让它不中断；
  - 评测让它可改进。
- 最终再次落下公式：`Harness = Agent − Model`。

## 6. 视觉系统

### 6.1 核心概念

视觉概念为 **“Agent 拆解实验室”**。

整套演示像一本可动的工业原理图：模型是一块高能核心模块，Harness 是围绕它工作的轨道、插槽、过滤器、刹车、检查点和仪表。禁止使用机器人形象、科幻星空和泛化的 AI 头像。

### 6.2 色彩

- 纸张底色：`#F2EBDD`
- 主墨色：`#111111`
- 模型 / 核心判断：信号橙 `#FF5A36`
- Harness / 系统结构：工程蓝 `#3157E1`
- 通过 / 安全 / 恢复：黄绿色 `#B8D84A`
- 信息面板白：`#FFFFFF`
- 次级文字与网格从主墨色和纸张底色派生，不引入额外装饰色。

语义规则：

- 橙色始终表示模型核心、关键观点或正在发生的推理。
- 蓝色始终表示 Harness 组件、系统控制或工具接口。
- 黄绿色只表示安全通过、恢复成功或验证完成。
- 错误状态使用主墨色高密度纹理或橙色警示，不新增红色主色。

### 6.3 字体

- 英文标题与公式：`Space Grotesk`
- 中文标题与正文：`Noto Sans SC`
- 状态、步骤与代码式标签：`JetBrains Mono`

排版层级：

- 封面主标题与总结标题：96–132px。
- 章节页与主问题：72–96px。
- 模块标题：36–52px。
- 投影正文：24–30px，不低于 24px。
- 辅助标签：14–18px，仅承担状态与来源标注。

### 6.4 网格、间距与组件

- 8px 基准单位。
- 页面安全边距约 88px。
- 主模块间距 32–48px。
- 卡片内部 24–36px。
- 主面板圆角 24px；工具模块圆角 12–16px；状态标签使用胶囊形。
- 统一 2px 黑色描边；危险动作或系统中断可短暂加粗。
- 阴影采用 1px 硬落边与低透明柔影组合，形成纸片和工业标签的质感。
- 连续两页不得重复同一种卡片网格。

### 6.5 页面构图家族

- 公式页：超大字号、少元素、强停顿。
- 原理页：中心装置与周边工程标注。
- 流程页：横向轨道或环形回路。
- 案例页：全屏大数字与单一因果组件。
- 实践页：内外两层剖面。
- 决策页：复杂度阶梯。

## 7. 动画系统

### 7.1 动画职责

所有动画必须承担以下至少一种功能：

1. **拆解**：解释 Agent 的组成；
2. **因果**：展示动作提出、执行和观察结果返回；
3. **筛选**：展示上下文从大量信息中选择相关部分；
4. **恢复**：展示中断后从 checkpoint 继续。

不为装饰而让所有元素浮入、旋转或持续漂移。

### 7.2 2D 动画

- 页面入场：500–800ms，使用自然减速曲线 `cubic-bezier(.22,1,.36,1)`。
- 模块装配：轻微惯性，不使用夸张弹簧。
- 连线流动：小型信号点沿路径移动，表示请求与观察结果。
- 公式变化：字符位置尽量稳定，只改变组成关系。
- 自动循环只用于第 8 页 Agent Loop；其他叙事动画进入页面时播放一次。
- 页面重新进入时必须重置到一致初始状态。

### 7.3 选择性 Three.js 3D

Three.js 只用于四个关键页面：

1. **01 封面**：Agent 装置缓慢旋转，模型核心与 Harness 模块处于爆炸拆解状态。
2. **03 核心公式**：外围模块从完整 Agent 脱离并重新组合为 `HARNESS`。
3. **07 全景剖面**：镜头推进 Agent 内部，当前模块前移高亮，其余退入背景。
4. **15 数据案例**：抽出并替换 `EDIT TOOL FORMAT` 接口，模型核心不变，指标切换。

3D 美术约束：

- 使用正交或弱透视镜头，不使用游戏式广角。
- 低多边形工业模块、清晰轮廓、纸张色表面。
- 仅使用已声明的橙、蓝、黄绿色和中性色。
- 柔和环境光与单一方向光，短且清晰的阴影。
- 不使用金属科幻材质、粒子星空、紫蓝霓虹、玻璃球和自由鼠标轨道控制。
- 镜头按预设轨迹运动，确保演示可控且每次播放一致。

### 7.4 降低动态与故障回退

- 遵守 `prefers-reduced-motion`。
- 降动效模式下取消镜头旋转、纵深飞行和路径运动，只保留最终状态切换与淡入。
- WebGL 不可用或 Three.js CDN 加载失败时，四个 3D 页面显示等义的 CSS/SVG 静态构图。
- 动画失败不得阻止翻页、全屏和页码更新。

## 8. 技术架构

### 8.1 交付物

- 新建单文件：`slides/Agent-Harness-Presentation.html`。
- 不覆盖或修改 `slides/TCP-Presentation-v2.html`。
- 不修改与本演示无关的现有未跟踪文件。

### 8.2 幻灯片引擎

- 固定内部画布 `1920×1080`。
- 通过 JavaScript 等比例缩放并在视口中居中，保持 16:9，不拉伸。
- 缩放容器外放置上一页、下一页和全屏按钮。
- 支持：
  - 左右方向键翻页；
  - 空格下一页；
  - 点击按钮翻页；
  - 全屏切换；
  - 页码和进度条；
  - 独立 `localStorage` key 保存当前页。
- 每页使用 1 起始标签，例如 `data-screen-label="01 Cover"`。

### 8.3 Three.js 加载与生命周期

根据 Three.js 官方现代浏览器用法：

- 使用固定版本 CDN ES Module，不使用旧式全局脚本模式。
- 通过 `importmap` 映射 `three`；实施版本固定为官方当前示例可用的 `0.185.0`，不使用浮动最新版 URL。
- 复用单个 WebGL renderer，避免为四页重复创建 WebGL 上下文。
- 只有当前 3D 页面激活时启动 animation loop。
- 离开 3D 页面时立即调用 `setAnimationLoop(null)` 或等价机制停止渲染。
- 场景不再需要时遍历对象并显式释放 geometry、material、texture；最终销毁时调用 renderer `dispose()`。
- 2D HTML 标注位于 canvas 上方，保证文字清晰、可访问且不依赖纹理渲染。

### 8.4 依赖策略

- 主要使用原生 HTML、CSS、SVG 和 JavaScript。
- Three.js 仅承担四个 3D 场景。
- 复杂 2D 路径编排可使用参考稿已有的固定版本 GSAP CDN；普通入场与状态变化优先使用 CSS 或 Web Animations API。
- 不引入 React、Chart.js、Anime.js、OrbitControls 或 Tweaks 面板。
- 外部依赖加载失败时，核心内容和翻页功能仍然可用。

## 9. 状态、清理与错误处理

- 幻灯片切换前停止上一页的定时器、requestAnimationFrame 和 Three.js animation loop。
- 进入页面前将其动画元素恢复到确定的初始状态。
- Agent Loop 的循环动画只允许存在一个实例。
- Three.js 资源通过统一资源注册表或场景遍历器释放，防止反复翻页造成 GPU 内存增长。
- `localStorage` 中页码越界或不可解析时回退到第 1 页。
- 全屏 API 被拒绝时记录非阻塞警告，不影响演示。
- CDN 或 WebGL 故障时添加 fallback class 并展示静态等义画面。

## 10. 可访问性

- 所有导航按钮有明确的 `aria-label` 和可见焦点态。
- 颜色不作为唯一语义信号；状态同时使用文字、形状或纹理。
- 正文不低于 24px，保持高对比。
- 关键 3D 内容均有 HTML 文本标题、说明和静态 fallback。
- 支持 `prefers-reduced-motion`。
- 键盘操作不依赖鼠标。

## 11. 验证标准

### 11.1 结构与导航

- 18 页全部存在并按 1 起始编号。
- 方向键、空格、按钮和全屏交互正常。
- 刷新后恢复上次页码。
- 首尾页不能越界。

### 11.2 布局

- 在 16:9、16:10 和窄窗口中保持完整 16:9 画面，使用留边而非裁切或拉伸。
- 所有正文和标注在 1920×1080 画布内无溢出。
- 投影正文不低于 24px。

### 11.3 动画与 3D

- 四个 3D 页面可按预设轨迹播放并正确重置。
- 离开页面后渲染循环停止。
- 反复进入 3D 页面不创建重复 renderer 或持续增长的资源。
- 其他动画不会叠加计时器或保留旧状态。
- 降动效模式下每页仍能理解因果关系。

### 11.4 故障回退

- Three.js 或 WebGL 不可用时，四个关键页面显示完整静态 fallback。
- GSAP 不可用时，页面仍然可见并可导航。
- 在线字体失败时回退字体不导致布局严重溢出。

### 11.5 内容准确性

- `Harness = Agent − Model` 在第 3、4、18 页保持一致表述。
- Grok 数据明确标注为报告引用的特定案例，不泛化成普遍因果承诺。
- MCP、HITL、持久化与评测只讲概念角色，不虚构产品能力或数据。

## 12. 成功标准

演示完成后，一位没有 Agent 工程背景的观众应能回答：

1. Harness 是什么？
2. 为什么裸模型不能直接成为可靠 Agent？
3. 循环、上下文、工具、护栏、持久化和评测各解决什么问题？
